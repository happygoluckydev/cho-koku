# cho-koku 要件定義書

- 版: 0.2（構成レビュー `docs/review-2026-09-03.md` を反映）
- 日付: 2026-09-03
- 作成: project-init による対話とレビューから作成

## 1. 背景と目的

「cho-koku」は「彫刻」（頭の中にある考えをはっきりと形に彫り出す）と「超克」（自分の考えを超える）のダブルミーニングを持つ、個人用のアイデア出し・ブラッシュアップツール。現在はチャットAI（ChatGPT等）をそのまま使ってアイデア出しをしているが、会話履歴が流れてしまい、アイデアの蓄積・比較・振り返りがしづらいという課題がある。

## 2. 対象ユーザー

開発者本人のみ。他人に使わせる予定はない。コードはGitHubで公開するが、公開はコードの見せ場としてであり、アプリの利用者を広げる意図はない。

## 3. スコープ

### 3.1 やること（初回リリース = MVP）

1. Webアプリ上でClaude（Anthropic API経由）とテキストで対話しながらアイデアを書き出す。対話ログがそのまま「記録」になる（記録とブラッシュアップは1つの統合機能）。
2. Claudeは対話中、必要に応じてDBに保存済みの過去のアイデアを参照できる（tool useによる簡易全文検索。ベクトル検索ではない）。
3. アイデアの保存は追記のみ（editやdeleteのUIは作らない）。

### 3.2 やらないこと

- 複数人での共有・コラボ機能 — 個人専用のため不要
- 音声入力・モバイルアプリ化（ネイティブアプリ） — レスポンシブWebで代替
- 多言語対応（i18n） — 利用者は自分のみ、日本語で十分
- アイデアの削除・編集UI — v1は追記のみ。修正が必要な場合は開発者が直接DBを操作する
- 通知・リマインド機能 — 振り返り機能自体がv2送りのため
- タグ付け・カテゴリ分類のUI — 関連付け・検索と合わせてv2で検討
- アプリ内のログイン・認証機能 — 認証は Cloudflare Access（メールアドレス認証）に委ね、アプリのコードには認証ロジックを持たせない（§6・§8参照）

### 3.3 将来検討（v2以降）

- 過去アイデアの振り返り（時間を置いての再掲示・思い出させる機能）
- アイデア同士の関連付け・検索のユーザー向けUI（pgvectorによる意味検索を想定）
- タグ付け・カテゴリ分類
- 通知・リマインド
- 編集・削除UI
- 複数端末間の認証（DBにuser_id列を予備で持たせてあるため、将来Supabase Authを足すだけで拡張できる）

## 4. 成功基準

1週間、ChatGPTなど他のチャットAIを使わずに、cho-kokuだけでアイデアの記録・AIとの対話ができている。

## 5. 機能要件

| # | 機能 | 優先度 |
|---|---|---|
| 1 | Webチャット画面でアイデアを書き、Claudeと対話する | Must |
| 2 | 対話ログをDBに保存する（追記のみ） | Must |
| 3 | Claudeが対話中に過去のアイデアを検索できるtool useを持つ | Must |
| 4 | アプリ全体を Cloudflare Access で保護する（AI呼び出しエンドポイントを含む） | Must |
| 5 | 過去アイデアの再掲示（振り返り） | Should（v2） |
| 6 | アイデア同士の関連付け・検索UI | Should（v2） |
| 7 | タグ付け・カテゴリ分類 | Could（v2） |

## 6. 非機能要件

- **性能**: 個人利用のみのため同時アクセスは考慮不要。
- **セキュリティ**: アプリの前段に Cloudflare Access（50ユーザーまで無料）を置き、メールアドレス認証を通過したリクエストだけをアプリに到達させる。アプリ側には認証コードを持たない。Supabase は `ideas` テーブルの RLS を有効にし、anon キー経由のアクセスを塞ぐ（サーバーはサービスロールキーで接続）。他人に使わせる段階になったら Supabase Auth の追加を検討する。
- **可用性・運用**: 止まっても業務影響はない個人ツール。Cloudflare Workers / Supabaseの無料枠内での運用を目指す。
- **データ**: アイデアの記録は消えると困るデータ。Supabaseの自動バックアップに依存する（§10 未決事項に具体的な取得方法を残す）。
- **対応環境**: PC・スマホのブラウザ。ネイティブアプリ化はしない。
- **i18n / a11y**: 対象外（自分専用、日本語のみ）。
- **法規・コンプライアンス**: 対象外。

## 7. 制約

- 期限: なし（個人開発、自分のペースで進める）
- チーム: 1人
- 技術: Next.js（TypeScript）、Supabase（Postgres）、Cloudflare Workers（`@opennextjs/cloudflare`）+ Cloudflare Access、Anthropic API
- 予算: 各サービスの無料枠内での運用を基本方針とする

## 8. リスクと対策

| リスク | 影響 | 対策 / 検知方法 |
|---|---|---|
| URLが漏れて第三者にAIエンドポイントを叩かれ、APIコストが発生する | Anthropic API課金 | Cloudflare Access のメール認証で防御。Anthropic側の利用上限アラートも設定する |
| Supabase / Cloudflareの無料枠を超過する | サービス停止 or 課金発生 | 要件定義書に上限を明記し、利用量を定期確認する（§10 未決事項） |
| アイデアデータが消失する | 記録の喪失（ツールの目的そのものが失われる） | Supabaseの自動バックアップに依存。定期エクスポート手段は未決（§10） |
| 一人開発でモチベーションが切れて放置される | ツール自体が使われなくなる | 成功基準（1週間の実利用）を早期に達成することを最初のマイルストーンにする |

## 9. 検討したが採用しなかった選択肢

| 選択肢 | 却下理由 | 再検討の条件 |
|---|---|---|
| CLI + ローカルMarkdownファイル（Git管理） | スマホ・ブラウザからのアクセスが必要という要件と両立しないため却下 | オフライン優先・スマホ不要になった場合 |
| 認証なしのクラウドDB直結ではなく複数PC間をGit自動同期する方式 | Web/スマホアクセスの要件を満たせないため却下 | 同上 |
| ホスティング/DBにAWSを使う | 個人開発には運用コスト・複雑さが重いため却下。Cloudflare/Supabaseで無料枠内に収まる | 大規模化やAWS固有サービスが必要になった場合 |
| 全部Cloudflare（DBもD1）に統一 | v2で想定するベクトル類似度検索（pgvector）との相性でSupabaseを優先 | ベクトル検索を諦める、またはD1+自前ベクトル実装で十分と判断した場合 |
| ログイン機能（Supabase Auth等）の実装 | 自分専用で利用者が増える予定がないため、実装コストに見合わない。認証は Cloudflare Access に委ねる | 他人に使わせる、または公開して使ってほしくなった場合 |
| 簡易トークンガード（`APP_API_TOKEN` をヘッダで照合） | ブラウザにトークンを渡す手段が未定義で、JSバンドルに含めると誰でも取り出せる。URL秘匿と同程度の強度しかない | Cloudflare Access が使えない環境に移す場合 |
| Cloudflare Pages + `@cloudflare/next-on-pages` | Cloudflare がメンテナンスモードとし、Workers + `@opennextjs/cloudflare` を推奨しているため | — |
| MVPに「振り返り」「関連付け・検索」を含める | 記録+ブラッシュアップの2機能に絞ることで最初のリリースを早める（YAGNI） | MVPが1週間安定稼働した後 |
| cho-kokuをMCPサーバー化し、任意のClaude Codeセッションから記録できるようにする | 記録元は「Claude（cho-koku内のチャット）」であり、外部連携は不要と判明したため | 外部ツール（エディタ等）からの記録ニーズが出てきた場合 |
| Claude連携用の`.mcp.json`（Supabase公式MCPサーバー等） | 実在するパッケージ名・設定値を公式ドキュメントで確認できなかったため、今回は見送り | 開発中にSupabaseへの対話的なDB操作が頻繁に必要になった場合、`claude mcp add`で個別に追加を検討 |

## 10. 未決事項

| 事項 | 決定期限 / トリガー | 暫定の進め方 |
|---|---|---|
| 無料枠を超えた場合の運用方針（都度判断 or 機能停止） | 無料枠の利用量が閾値（各サービスダッシュボードで確認）に近づいた時点 | 一旦は都度手動確認。自動停止の仕組みは作らない |
| データのバックアップ具体的な取得方法・頻度 | MVPリリース後、実データが増え始めた時点 | 当面はSupabaseの自動バックアップに依存 |
| Anthropic APIの利用料金の負担・上限設定 | 実際に使い始めて費用感が見えた時点 | Anthropicコンソールで利用上限アラートを設定してから開始する |
| ~~簡易トークンガードで十分か、将来Supabase Authに切り替えるか~~ | 2026-09-03 決定 | Cloudflare Access を前段に置く（§6）。Supabase Auth は他人に使わせる段階で再検討 |

## 11. 用語集

| 用語 | この文書での意味 |
|---|---|
| アイデア（記録） | cho-koku内でClaudeと交わした一連の対話ログ1件 |
| ブラッシュアップ | Claudeとの対話によってアイデアを深める行為。記録と同一の対話フローの中で行われる |
| 振り返り | 過去のアイデアを時間を置いて再度提示し、思い出させる機能（v2） |
