## 全体評価

構成は MVP の規模に対して適切で、`CLAUDE.md` と `docs/requirements.md` の品質は高い。ただし現状は「設計済みの骨組み」であり、`src/` 配下の全ファイルがコメント1〜2行だけの空ファイルである。`pnpm build` は今の状態では失敗する。

## 直したほうがよい点（重要度順）

### 1. 「追記のみ」の方針と `ideas` テーブルの設計が矛盾している（最重要）

`ideas.transcript` に対話ログ全体を1行の JSONB として持つ設計だが、対話は何ターンも続く。ターンが進むたびに同じ行を UPDATE するか、毎回スナップショット行を INSERT するかのどちらかになり、前者は追記のみの方針に反し、後者は無駄が大きい。`summary` を「Claude に生成させる」タイミングも同じ問題を抱える。

**推奨**: `ideas`（セッションのヘッダ）と `idea_messages`（`idea_id`, `role`, `content`, `created_at`）の2テーブルに分け、メッセージ単位で INSERT する。

### 2. `pnpm deploy` は pnpm の組み込みコマンドと衝突する

`pnpm deploy` は pnpm 自身のワークスペース用コマンドのため、`package.json` の `deploy` スクリプトは実行されない。`CLAUDE.md` と `.claude/settings.json` の `ask` 設定も同じ名前を前提にしている。

**推奨**: `pnpm run deploy` に統一するか、スクリプト名を `deploy:cf` などに変える。

### 3. `deploy` スクリプトの中身が Cloudflare Pages では動かない

`next build && wrangler pages deploy` は出力ディレクトリの指定がなく、`.next/` はそのまま Pages にデプロイできない。`wrangler.toml` にも `pages_build_output_dir` がない。また Cloudflare は現在 `@cloudflare/next-on-pages` をメンテナンスモードとし、`@opennextjs/cloudflare` で Workers にデプロイする方式を推奨している。

**推奨**: Pages か Workers かを早めに決める。`next.config.ts` と API ルートの書き方に影響する。

### 4. `APP_API_TOKEN` をブラウザに埋め込むと URL 秘匿と同等の強度しかない

`.env.example` に「クライアントとサーバーで同じ値を共有」とあるが、`NEXT_PUBLIC_` 接頭辞がないのでクライアントからは読めない。ブラウザにどう渡すかが未定義。JS バンドルに含めると誰でも取り出せる。

**推奨案**:
- 初回アクセス時にトークンを手入力させ、localStorage に保存する
- Cloudflare Access（50ユーザーまで無料）をアプリの前段に置く。コード0行でメールアドレス認証が付き、要件 §6 と §10 の未決事項がまとめて解決する

### 5. RLS が有効になっていない

Supabase は PostgREST でテーブルを公開するため、RLS 無効のテーブルはダッシュボードで警告が出る。サービスロールキーは RLS をバイパスするので、以下をポリシーなしで追加するだけで anon 経由のアクセスを塞げる。

```sql
alter table ideas enable row level security;
```

### 6. 日本語の全文検索は `to_tsvector` では機能しない

マイグレーションのコメントで `to_tsvector` を想定しているが、Postgres 標準の設定は日本語を分かち書きできない。

**推奨**: `pg_trgm` 拡張と GIN インデックス + `ILIKE`、または Supabase で使える `pgroonga` を検討する。

### 7. 公開リポジトリなのに LICENSE がない

要件 §2 に「コードは GitHub で公開」とあるので、MIT などのライセンスファイルを置く。

## 軽微な点

- **デフォルトブランチ**が `claude/new-project-setup-qyb45c` になっている。最初にプッシュされたブランチが自動でデフォルトになったため。`main` を作ってデフォルトを切り替える。
- **`@anthropic-ai/sdk ^0.32.0` は 2024年末のバージョン**で古い。最新版に上げ、モデル ID は `claude-opus-5` を使う。過去アイデア検索の tool use は SDK の `betaZodTool` + `toolRunner` でループを書かずに実装できる。
- **`pnpm-lock.yaml` と `packageManager` フィールド**がない。再現性のため両方コミットする。
- **ESLint 設定ファイルがない**ため `pnpm lint` は初回に対話プロンプトを出す。`eslint.config.mjs` を置く。
- **`typecheck` スクリプト**（`tsc --noEmit`）がなく、テストの仕組みも未定。MVP でも型チェックだけは安価なので追加する。
- **`src/types/idea.ts` の `transcript: unknown`** は SDK の `Anthropic.MessageParam[]` を使えば型安全になる。ただし指摘1の設計変更でこの型自体が変わる。
- **db-migration スキルの命名規則** `NNNN_<verb>_<what>.sql` と既存の `0001_init.sql` が一致していない。
- **README の構成図**に `layout.tsx` と `lib/` 配下のファイル名がなく、`CLAUDE.md` の説明より粗い。片方に寄せるか README から `CLAUDE.md` へ委譲する一文で十分。

## 良い点

- `CLAUDE.md` が「何を」だけでなく「なぜ」を書いており、境界ルール（Supabase は `ideas.ts` 経由のみ、Anthropic API は `route.ts` のみ）が明確。
- `docs/requirements.md` の §9「採用しなかった選択肢」と §10「未決事項」が具体的で、後から判断を追える。
- `.claude/settings.json` の allow / ask / deny の切り分けと、`.env*` の Read 拒否は適切。
- `.gitignore` で `.env.*` を除外しつつ `.env.example` だけ許可しているのは正しい。
